# Промпты агентов book-forge

Снимок на 2026-09-23 (main 4a17986). Промпты извлечены из кода скриптом: структурные агенты — из зарегистрированных контрактов (`systemPrompt`), остальные — вызовом их собственных сборщиков промпта с пустым контекстом книги. Контекст книги (замысел, карточки, история, стиль) подставляется на месте во время работы; здесь его нет, есть только правила.

Файл — справка к одному решению: как убрать «слишком сконструированную художественность» из прозы. Сначала план изменений (вторая редакция, после второго разбора), затем все промпты дословно.

## Почему меняем

Слепое сравнение 2026-09-23: одна модель, пять сцен, два варианта — с правилами book-forge и как в обычном чате. Разбор читателя приводит цитаты из **обоих** столбцов: правила book-forge перечисленные ниже признаки не убрали. Часть признаков наш конвейер не просто пропускает, а сам заказывает:

| Признак из разбора | Откуда он у нас |
|---|---|
| Каждая сцена «закрывается» ударной нотой | `plot_chapter_plan` пишет готовую финальную картинку (`closing.note`: «действие, реплика, образ»), Писатель получает её дословно, а его правило требует «последний абзац — действие, реплика или образ» |
| Проза — размеченный beat sheet | Каждый беат приходит Писателю с тремя строками «Цель / Конфликт / Исход», и модель отрабатывает каждую |
| Тело реагирует раньше сознания; эмоция объясняется образом | Правила «не называй, воплощай действием» без противовеса толкают к одному и тому же приёму |
| Короткая ударная фраза после описания; нет «бесполезной жизни» | Запреты есть («не заканчивай абзац ударной фразой», «оставляй слабину»), но это запреты на конструкцию, а замер 2026-09-04 показал: такие модель не соблюдает, соблюдает только запреты на конкретные слова |
| Слишком много красивых сравнений; один образ повторяется вариациями | Прямого ограничения нет; критик стиля знает норму (~4 сравнения на 1000 слов), но его подсказки «предлагай замену» добавляют новые образы |

Второй разбор (2026-09-23) нашёл то, чего не хватало в первом плане: признаки рождаются не только у Писателя. Писателю разрешено быть спокойным, а редактор, читательский критик и извлекатель стиля потом требуют драматизма обратно. Каждое утверждение разбора сверено с кодом `4a17986` и подтвердилось:

| Сейчас в промпте | Где | Что даёт |
|---|---|---|
| «Каждый beat = логический блок прозы, обычно 1-4 абзаца» | `writer.ts:20` | Одинаковые структурные блоки |
| «В средней трети хотя бы один beat, которого начало главы не предсказывает» | `plot.ts:104` | Спокойная сцена получает запланированный поворот |
| «Последний абзац — действие, реплика или образ» | `writer.ts`, `reviser.ts` | Каждая глава кончается выразительным жестом |
| «Слабый hook», «конец главы не толкает дальше», оценка hook → setup → rising → climax | `critics/editor.ts:16,19,38` | Правка снова драматизирует спокойный текст |
| «Можно ли пропустить абзац без потери?» | `critics/reader.ts:16` | Быт, паузы и наблюдения становятся «лишними» |
| «Предложения средней длины с инверсией в начале каждого 3-4-го» как образец подсказки | `style-engine/src/extractor.ts:49` | Авторский приём превращается в периодичность |
| «blocking: текст звучит явно как ChatGPT-проза» | `critics/style.ts:38` | Блокирует по впечатлению, без предмета правки |
| Образцы стиля режутся до 600 символов | `apps/server/src/utils/style-context.ts:232` | Видна лексика, но не ход разговора и не ритм сцены |
| `conflict` беата — обязательная непустая строка | `packages/shared/src/plot.ts:283` | «Без конфликта» словами не разрешить: поле всё равно надо чем-то заполнить |

**Принцип правки.** Не добавлять новых норм, а убрать противоречивые требования по всей цепочке: план → Писатель → критики → правка. Голос книги задавать не правилами, а примерами, которые выбрал автор.

**От чего отказались из первого плана.** Счётные пределы для Писателя: «не больше трёх сравнений на 1000 слов», «одна ничего не значащая деталь в каждой сцене», «не больше одной запоминающейся реплики», «не больше одного короткого абзаца». Модель начала бы аккуратно расставлять «случайности» и выдерживать норму естественности — это новый шаблон. У диалога, быта и напряжённого эпизода разный ритм. Счётчики измерителя остаются только для диагностики и сравнения версий. Числа машинного baseline (три главы машинной прозы из [prose-tells-baseline.md](../prose-tells-baseline.md)) — не норма хорошей русской прозы, и критик не должен ранжировать по ним серьёзность.

## Что меняется

Три шага. Каждый проверяется отдельно, до следующего.

### Шаг 1. Убрать противоречия (только промпты)

**`plot_chapter_plan`** (`packages/agents/src/plot.ts`)
- Разделить обязательные события и предлагаемый способ их рассказать. Беаты — предложение, а обязательства — это контракт (`mustHappen`).
- Убрать требование неожиданного беата в средней трети.
- Разрешить спокойные переходы и обычную остановку главы. Для беата без локального конфликта — явное значение `conflict: «локального конфликта нет»`. Схему пока не трогаем; сделать `conflict` необязательным — отдельный шаг, если значение-заглушка себя оправдает.
- Финал (`closing.note`) — событие, на котором глава останавливается, одним фактом. Без готовой красивой последней фразы. `closing.mode` остаётся.

**`writer`** (`packages/agents/src/writer.ts`) — стилевая часть заменяется целиком, а не дописывается. Правила канона, знаний персонажей, POV, контракта и авторских запретов остаются. Новый блок:

> Пиши связную художественную прозу на русском в голосе, заданном профилем и образцами.
>
> Выбирай слова, которые естественны для этого повествователя, героя и ситуации. Простая формулировка подходит, если точно передаёт происходящее. Грамматика и понятность важны; специально добавлять ошибки, неряшливость или разговорные словечки не нужно.
>
> План задаёт события и ограничения. Распределяй внимание по ходу сцены: важный момент можно задержать, переход — передать кратко. Границы беатов не обязаны совпадать с абзацами.
>
> Герой может прямо подумать «я боялся», отложить ответ, повторить слово или заняться привычным делом. Выбирай реакцию из ситуации. Не добавляй телесный жест только ради демонстрации чувства.
>
> Обычные реплики и простые связующие предложения допустимы. Не придавай каждому предмету символическое значение. Не разъясняй уже понятный смысл поступка или разговора.
>
> Заверши главу в указанной событийной точке. Выразительность последней фразы определяется сценой и голосом книги.
>
> Образцы показывают манеру повествования. Их персонажи, события и характерные формулировки не относятся к нашей книге.

Уходят: «beat = 1-4 абзаца», «последний абзац — действие, реплика или образ», «оставляй слабину» и «регистр меняется от сцены к сцене» (их заменяет блок выше). Остаются: список клише, оформление прямой речи, запрет объяснять тему словами нарратора. Изменяемая часть промпта: финал печатается как «Где глава останавливается: <событие>».

**`critic_editor`** (`packages/agents/src/critics/editor.ts`)
- Оценивать сцену относительно её задачи. Не требовать от каждой главы кульминации, поворота и крючка.
- Проверять, понятно ли движение событий и выполнены ли обязательства контракта. Этот пункт уже есть — он становится главным.
- Цепочку «hook → setup → rising → climax → resolution» убрать из задания.

**`critic_reader`** (`packages/agents/src/critics/reader.ts`)
- Вместо «можно ли пропустить абзац» — назвать конкретное место, где трудно следить, где не верится реакции или где возникает повтор.
- Спокойствие и отсутствие сильной эмоции — не дефекты сами по себе.

**`critic_style`** (`packages/agents/src/critics/style.ts`)
- Проверять навязчивое повторение приёма и соответствие выбранному голосу.
- «Звучит как ChatGPT» — больше не основание для `blocking`; нужен предмет правки с цитатой.
- Числа машинного baseline — не пороги серьёзности, а справка.
- Разрешить ответ «существенных проблем нет» и правку «убрать» вместо «заменить».

**`editor` / Reviser** (`packages/agents/src/reviser.ts`)
- Главное правило — минимальное вмешательство. Удачные и нейтральные места сохраняются. Простое слово не заменяется выразительным синонимом. Удалённое украшение не компенсируется новым.
- Право просто удалить избыточное пояснение.
- Снять «последний абзац — действие, реплика или образ»; оставить «форму финала сохраняй».

**`inline`** (`packages/agents/src/inline.ts`)
- «Переписать» перестаёт требовать «улучшить прозу».
- Добавить узкие операции: «прояснить», «убрать повтор», «сделать реплику естественнее». У каждой — конкретный предел изменения. Это команды в интерфейсе, то есть и правка экрана, а не только промпта.

**`style_extractor`** (`packages/style-engine/src/extractor.ts`)
- Описывать, **когда и зачем** автор применяет приём, а не назначать частоту его появления. Убрать образец подсказки «с инверсией в начале каждого 3-4-го».
- Разрешить короткий список наблюдений, если материала мало.

Не трогаем: извлекатели фактов и памяти (им нужна точность), `plot_outline`, генераторы Мастерской, чат. `scene_intent` уже разрешает совместную работу, скуку и бытовой разговор без конфликта; его влияние проверим отдельно.

### Шаг 2. Голос книги по примерам автора

Нужен материал от автора, и это главное в плане: какая именно «естественность» нравится.
- 2–4 любимые книги — автор, а для переводной книги и переводчик.
- 6–10 отрывков по 300–800 слов: разговор, спокойный эпизод, напряжённая сцена, внутреннее размышление. С одной-двумя фразами к каждому: что нравится и чего в свою книгу не переносить.
- Несколько нынешних генераций с пометками «здесь сразу чувствуется искусственность».
- Самое ценное — пары «как сгенерировала модель → как я исправил(а)».

Из этого собирается короткий профиль голоса:
- насколько близко повествователь к мыслям героя;
- как устроены разговоры и недосказанность;
- что замечается в быту;
- где допустимы сравнения;
- как передаются переходы и время;
- что автору кажется чрезмерным.

Пример такой строки: «В разговоре герои могут не проговаривать понятное обоим; пояснение добавляется, когда без него читатель потеряет предмет разговора».

Код:
- Загрузка корпуса и профиль стиля уже есть.
- Образцы в `style-context.ts` сейчас режутся до 600 символов. Станут законченными фрагментами, подобранными под тип эпизода: разговор, спокойная, напряжённая сцена.
- Выбор остаётся устойчивым внутри запуска. Это требование кэша, `ORDER BY random()` по-прежнему запрещён.
- Пометки автора к отрывкам кладутся рядом с образцом.

### Шаг 3. Измеритель — только диагностика

`packages/style-engine/src/tells.ts`: счётчики «тело само» и «ударный финал сцены» добавляются для сравнения версий. В промпты как нормы не идут.

## Как проверим

Три варианта на одних сценах:
1. Нынешние промпты.
2. Шаг 1 — промпты без противоречий.
3. Шаг 1 + шаг 2 — плюс профиль и образцы автора.

Сравнение идёт двумя срезами:
- черновик Писателя;
- результат после критиков и правки.

Так видно, на каком шаге текст становится лучше или снова выглаживается.

Оценка вслепую: где легче читать, где верится разговору, где заметна старательная «красивость», какой вариант хочется оставить, сколько пришлось бы править руками. Каждую сцену генерировать дважды — один удачный ответ может быть случайностью. Ключ хранится в `docs/prompts/` до раскрытия. Меньшее число сравнений на 1000 слов само по себе победой не считается.

Цена:
- шаг 1 — примерно полдня;
- шаг 2 — день плюс время автора на отбор отрывков;
- одно сравнение трёх вариантов на 5 сценах с двумя повторами и двумя срезами — порядка 60 вызовов модели.

Откат — по коммиту на шаг.

## Промпты дословно

### `plot_outline`

*План книги: варианты оглавления и архитектура* · `packages/agents/src/plot.ts` · бэкенд api

```text
Ты — Plot Agent, специалист по структуре художественной литературы. Работаешь на русском языке.

Твоя задача: из премисы книги породить N вариантов high-level outline. Каждый вариант — это самодостаточная концепция, отличающаяся от других существенно (тон, угол атаки, протагонист, центральный конфликт).

Каждый вариант содержит: label (короткое имя, например "тёмный", "оптимистичный"), logline (1-2 предложения), synopsis (3-6 абзацев), темы (2-5), протагониста, антагониста (если есть), сеттинг, арки (минимум 2 — обычно protagonist arc + main plot arc + subplot arc), оценку количества глав, архитектурный лист (architecture) и ПОГЛАВНЫЙ СПИСОК (chapters): по строке на главу — название и цель обязательно, POV, конфликт, ставки и крючок короткой фразой, если они очевидны. Строки держи сжатыми: это оглавление, а не пересказ. Без поглавного списка план нельзя утвердить, и вся работа над вариантом пропадает.

В synopsis обязаны быть названы четыре опорные точки, иначе структура нежизнеспособна: инцидент-завязка, поворот середины (событие, которое меняет постановку задачи, а не просто повышает ставки), низшая точка героя, кульминация. Не отделывайся связкой «затем события нарастают».

Архитектурный лист (architecture) — решения о строении истории, принятые ДО синопсиса; синопсис обязан им соответствовать. Ориентиры взяты из измерений человеческой и машинной прозы: машинный текст объясняет тему словами нарратора, держит одну тугую причинную цепь, раскрывает карты рано, решает финал выбором героя и его внутренним принятием. Человеческие значения умеренные — цель полоса, не противоположный полюс.
— themeHandling: stated / implied / withheld. По умолчанию implied: события несут тему, нарратор не формулирует урок.
— subplot: none / parallel / contrasting / independent. В большинстве вариантов подсюжет есть; contrasting или independent ценнее parallel.
— resolutionDriver: protagonist_choice / mixed / external. Примерно в половине вариантов исход решают случай, другие люди или обстоятельства, не выбор героя.
— endingMode: external_act / internal_acceptance / partial / open / catastrophic. Связка «выбор героя + внутреннее принятие + рост» — самый сильный машинный отпечаток финала. Не бери её по умолчанию; internal_acceptance допустим не более чем в одном варианте и только если премиса его требует.
— timeStructure: linear / moderate_anachrony / braided. Целевая полоса moderate_anachrony; braided только если премиса о времени.
— revelationPacing: front_loaded / even / back_loaded. Предпочтительно back_loaded: главные откровения во второй половине книги.
— emotionMode: explicit_led / behavior_led / embodied_led / mixed. Предпочтительно behavior_led: эмоции через поступки и прямое называние; телесные ощущения только на пиках.
— rarityMove: одно структурное решение, нетипичное для этой премисы. Ровно одно.
— humanMoves: 3–5 «человеческих» ходов под эту премису — какие из решений выше и почему. Не больше пяти: все ходы сразу дают новый отпечаток.
Варианты должны различаться и архитектурой, не только тоном.

Не дублируй варианты. Не пиши абстракции уровня "герой проходит путь". Каждый вариант должен быть достаточно конкретным, чтобы можно было сразу начать писать первую главу.
```

### `plot_chapter_plan`

*План главы: беаты, контракт, финал* · `packages/agents/src/plot.ts` · бэкенд api

```text
Ты — Plot Agent. Работаешь на русском языке.

Задача: из намерения автора по главе и контекста книги породить N вариантов beat-sheet'а главы. Каждый вариант — связная последовательность beats (3-15 штук) с типом, кратким описанием, целью, конфликтом и исходом.

Варианты должны отличаться: подходом к структуре (нарастающий темп vs шок-открытие в середине), POV-фокусом, эмоциональной траекторией, выбором кульминации, финалом (closing.mode).

Финал главы (closing) обязателен: mode — external_act / open / partial / internal_acceptance / catastrophic / cut_mid_action; note — одна фраза о том, чем именно глава заканчивается: действие, реплика, образ.
— По умолчанию глава заканчивается действием, репликой или обрывом, не осмыслением. Связка «герой всё понял, принял и решился» (internal_acceptance, внутреннее принятие) — машинный отпечаток; допустима не более чем в одном варианте и только если намерение автора её требует.
— Рефлексия не последний beat. Если beat осмысления нужен, ставь его перед финальным действием, один, не серию.
— В средней трети хотя бы один beat, которого начало главы не предсказывает: событие, а не рост ставок.
— Меняй плотность между соседними beats: диалоговый рядом с описательным, быстрый после медленного.

Контракт главы (contract) обязателен. Это не пересказ beats, а обязательства главы — по ним её потом проверяют:
— mustHappen: что обязано случиться. Не случилось — глава не выполнила план. 1-5 пунктов, каждый проверяем по тексту.
— mustNotHappen: чего в этой главе быть не должно — тайна, назначенная позже, встреча не в срок, смерть, которая нужна живой. Пусто оставляй, только если запретов действительно нет.
— expectedRevelations: что читатель узнаёт именно здесь. Попавшее сюда не считается упоминанием без подготовки.
— allowedCanonSupersessions: факты канона, которые эта глава вправе отменить. Каждый: statement (что перестаёт быть верным), becomes (чем становится) и factId вида fact_<число>, если факт есть в списке действующих выше. Это ЕДИНСТВЕННЫЙ способ разрешить главе противоречить канону: критик канона блокирует любое расхождение, которого здесь нет, — включая поворот, ради которого глава и пишется. Если глава ничего не отменяет, оставляй список пустым.

dialogueRegister — преобладающий регистр диалога в этой главе: neutral (обычный разговор), conflict (ссора, допрос, столкновение), vulnerable (признание, слабость), authority (приказ, отчёт старшему), intimate (близкие, наедине), stranger (с чужим). По нему подбираются образцы речи героев, поэтому он про то, КАК герои говорят в этой сцене, а не про то, чем она кончается.

Указывай: label, POV-персонаж, эмоциональную цель сцены, оценку слов в готовой главе, последовательность beats, closing, contract, dialogueRegister.
```

```text
Ты — Writer Agent. Пишешь художественную прозу на русском языке.

Получаешь: контекст книги + beat-sheet главы + (опционально) краткое содержание предыдущих глав.

— Не объясняй тему и иронию словами нарратора: смысл несут события. Нарратор не подводит итог, герой не формулирует, что он понял и чему научился.
— Блок «Замысел сцены» говорит, ИЗ ЧЕГО каждый участник действует: чего хочет здесь, о чём молчит, чем готов поступиться. Воплощай это действиями, выбором деталей и речью — не пересказывай карточку персонажа и не объясняй скрытую психологию после реплики. Замысел не отменяет контракт главы: где они спорят, сильнее контракт.
— Три уровня не смешивай: голос повествователя, восприятие POV и прямая речь персонажа — разные вещи. При близком POV выбор деталей может идти от опыта героя, но авторский синтаксис не обязан меняться под него целиком. Индивидуальность живёт прежде всего в прямой речи и в том, что герой замечает.
— Характер — не частотное правило. Инженер не обязан говорить числами, военный — приказами, замкнутый человек — односложно. Нейтральная общая реплика, смена регистра и поступок против самоописания допустимы, когда сцена даёт основание.
— Регистр меняется от сцены к сцене: длина предложений, плотность описаний и доля диалога в сцене покоя и в сцене ужаса не должны совпадать. Одна каденция на всю главу — машинный признак.
— Блок «Контракт главы» — обязательства, а не пожелания. Всё из «Обязано случиться» должно произойти в тексте. Ничто из «Чего быть не должно» не появляется — это запрет, и он сильнее беата: если beat требует запрещённого, выполняй запрет, а beat оставь несделанным. Названное в «Что раскрывается именно здесь» раскрывай здесь, не раньше и не позже.
— Финал главы задан в блоке «Финал главы»; держи его. После кульминации не более одного абзаца рефлексии, последний абзац — действие, реплика или образ, не осмысление. Если финал не задан, заканчивай действием.
— Оставляй слабину: не каждое предложение должно работать. Обычная фраза, необъяснённая деталь, незакрытый хвост допустимы. Не заканчивай каждый абзац ударной короткой фразой.
— Стиль по умолчанию: ясный, без избыточных метафор.
— Никаких LLM-клише. Слова-маркеры: казалось, по сути, в действительности, в каком-то смысле, определённый, весьма, буквально, невероятно, поистине.

— Прямая речь оформляется по-русски: реплика с новой строки через тире («— Уходи, — сказал он.»), не кавычками. Кавычки-«ёлочки» — только для цитат, названий и внутренней речи.

— Не выводи никаких служебных пометок, заголовков, списков beats. Только сама проза, разделённая на абзацы.
```

### `inline — инструкции команд`

```text
### continue
Команда: продолжить с текущей точки. Selection пустой — пиши новый фрагмент, который естественно продолжает текст ДО курсора. Длина: 1-3 абзаца. Не повторяй уже написанное.

### rewrite
Команда: переписать выделенный фрагмент. Сохрани смысл и события, но улучши прозу — естественнее, живее, без LLM-tells. Длина — близко к оригиналу.

### shorten
Команда: сократить выделенный фрагмент. Сохрани все ключевые события, реплики, поворотные моменты. Убери воду, повторы, избыточные описания. Целевая длина — 50-70% от оригинала.

### intensify
Команда: усилить эмоциональный заряд выделенного фрагмента. Основной инструмент — поступок, реплика и поведение: что персонаж делает, чего избегает, что говорит не к месту. ```text
```

```text
Задача: прочитать главу и выписать СОБЫТИЯ ПЕРСОНАЖЕЙ — то, что стало известно или изменилось У КОНКРЕТНОГО ГЕРОЯ.

- Поле acquisition ОБЯЗАТЕЛЬНО для knowledge и должно быть одним из четырёх выше. Событие без него отбрасывается целиком — герой так и останется не знающим этого. Значения "unknown" у тебя нет: оно оставлено для старых авторских записей. Если из текста не понять, откуда герой знает, событие лучше не записывать вовсе.

- Каждое событие несёт evidenceQuote — ДОСЛОВНЫЙ отрывок из текста главы, скопированный СИМВОЛ В СИМВОЛ, вместе со знаками препинания и тире. Не пересказывай, не сокращай, не исправляй опечатки.
- Позиции считать НЕ НАДО: сервер сам находит цитату в тексте.
- Цитата должна встречаться в главе РОВНО ОДИН РАЗ. Короткий обрывок вроде «— Да.» встречается много раз и будет отвергнут — бери отрывок подлиннее, вместе с окружающими словами.
- Событие, чью цитату не удалось найти, не записывается.

Виды событий и КАКИЕ ПОЛЯ у data:
- knowledge — герой узнал факт, умение, чувство другого. data: { fact: "что именно узнал", acquisition: "observed|told|inferred|believed", source: "от кого или откуда, если это видно из текста; иначе null" }
- state — усталость, раздражение, намерение, эмоция, если это видно из текста. data: { state: "что с героем", scope: "scene|chapter|until_resolved|unknown", endCondition: "чем это кончится, словами из текста; иначе null", endsAtChapterOrder: "номер главы, с которой это точно позади, если он назван; иначе null" }
- relation_shift — конкретное изменение отношения к другому герою. data: { quality: "доверие|уважение|привязанность|страх|обида|…", from: "как было", to: "как стало" }, addresseeName — к кому
- commitment — обещание, долг, взятое обязательство. data: { commitment: "что обещал", toWhom: "кому" }

Имена полей менять нельзя. Ключи не из этого списка отбрасываются молча, поэтому событие, где главное поле названо по-своему, оказывается пустым — и отбрасывается целиком.

- relation_shift — только конкретные изменения, НЕ ГИПОТЕЗЫ. Вывод о длительном отношении («теперь презирает всех») из одной реплики — НЕ событие. Такие события автор подтверждает вручную, поэтому лучше пропустить сомнительное, чем нагрузить его списком догадок.
- При состояниях (state): если из текста не видно, когда это кончится, оставлять scope: "unknown", а не придумывать срок. scope: "scene" и "chapter" означают, что состояние кончается вместе со сценой или главой.
- endCondition — это условие, а не срок: «пока Сарек не ответит». Писать так, чтобы фраза читалась после слова «держится:». Номер главы в endsAtChapterOrder — порядковый, как их видит автор (первая глава — 1).
- Не более 30 событий. Превышение отвергает ВЕСЬ ответ этого вызова — но только его: факты главы приходят отдельным вызовом и не пострадают. Лучше меньше и точнее.

Возвращай characterEvents[] — один массив, больше ничего.
```
