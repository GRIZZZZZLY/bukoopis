# Заимствования из litrab.ai — спецификация

Дата: 2026-09-21. Источник: разбор сайта и 31 статьи блога litrab.ai (ИИ-помощник для авторов длинной прозы). Из их продукта взяты восемь приёмов, которых в book-forge не было или которые у нас работали хуже. Их архитектурный выбор — «вся книга в контекст, а не RAG» — не берём: наша слоистая память с границами сцены глубже и на длинной книге дешевле.

Каждый пункт — самостоятельный кусок работы; порядок в плане — от дешёвого к дорогому. Все восемь ложатся в одну миграцию `0032_litrab_borrowings`.

## Общие правила (действуют на все пункты)

- Ничего не утверждается без автора: ни чат, ни «Описать», ни битовая генерация не пишут в главу сами. Всё приходит кандидатом или вставкой по кнопке.
- Один экземпляр логики на всех читателей: фильтр скрытых героев — в `gatherCharacterContext`, сборка контекста чата — через `assembleGenerationContext`, вставка корпуса — одним хелпером.
- Русский интерфейс; слова «промпт», «токен» на экране не появляются — «запрос к модели», «объём».
- Десктоп; мобильная вёрстка не проверяется (locked decision).
- Тесты мокают модель (`vi.mock("@book-forge/agents", …)`), маршруты проверяются через `makeTestApp`.

## 1. Другие имена героя (экран над существующим API)

**Что у Литраба.** В карточке героя поле «Другие имена» — прозвища, титулы, варианты; по нему модель понимает, что «Ваше Сиятельство» и «Алексей» — один человек.

**Что у нас.** Таблица `entity_aliases` и маршруты `GET/POST /books/:id/entities/:type/:entityId/aliases`, `DELETE /books/:id/aliases/:aliasId` есть с ADR 0003; резолвер их читает. Экрана нет — записано в CLAUDE.md как долг, из-за которого события героини «Нины/Агаты» отвергались все до одного.

**Решение.** Только фронтенд плюс общий тип.
- `packages/shared/src/entities.ts`: `entityAliasSchema = { id, alias, createdAt }`, тип `EntityAlias`. Сервер (`utils/entity-resolve.ts`) импортирует тип оттуда вместо своего.
- `apps/web/src/api/client.ts`: `listCharacterAliases(bookId, characterId)`, `addCharacterAlias(bookId, characterId, alias)`, `deleteAlias(bookId, aliasId)`.
- `KnowledgePanel.tsx` → карточка героя получает блок «Другие имена»: чипы с крестиком, поле «+ имя», Enter добавляет. Ошибка 400 «alias already maps to entity N» показывается текстом «Это имя уже закреплено за другим героем».
- Компонент `AliasEditor` в `apps/web/src/components/AliasEditor.tsx` — свой файл, тест рядом.

Не делаем: псевдонимы мест и предметов на экране (API их принимает, но интейк и события работают по героям; добавить — один проп `entityType`).

## 2. Сырые заметки автора

**Что у Литраба.** Раздел Досье, который принципиально не подмешивается в запросы: держать там можно сколько угодно.

**Что у нас.** Всё, что автор пишет, либо уходит в промпт, либо не существует. Поэпизодный план, ссылки, «не забыть» — некуда.

**Решение.**
- `books.author_notes TEXT NULL` (миграция 0032). `Book.authorNotes: string | null`; `updateBookInputSchema.authorNotes: z.string().max(200_000).nullable().optional()`; `PATCH /books/:id` пишет колонку; `toBook` отдаёт.
- Панель «Заметки автора» (`apps/web/src/components/chapter/AuthorNotesPanel.tsx`) в правой колонке страницы главы под `PanelBoundary`: textarea, автосохранение через `useDebouncedSave` (1 с, повторы по умолчанию), подпись «В запросы к модели не уходит».
- **Инвариант**: ни одна сборка контекста не читает `author_notes`. Закреплён тестом: в `generation-context` сеется книга с заметкой-маячком, и маячок не встречается ни в одном строковом поле `AssembledContext`, ни в `studioContextToPrompt(loadStudioContext(...))`.
- `GET /books/:id/export.json` включает заметки (страховка): проверяется тестом; если выгрузка берёт строку книги не целиком — поле добавляется.

## 3. «Глазок» — герой вне запросов

**Что у Литраба.** У карточки есть глазок; снятый — карточка не уходит ни в чат, ни в «Продолжить». Для героев, которых нет в текущих главах.

**Что у нас.** Состав сцены отбирается автоматически по упоминанию имени в плане/тексте (`gatherCharacterContext`). Ручного «этого не бери» нет; герой с частым именем («Мать») попадает в каждую сцену.

**Решение.**
- `characters.hidden_from_prompts INTEGER NOT NULL DEFAULT 0` (миграция 0032). `Character.hiddenFromPrompts: boolean`.
- `PATCH /characters/:id/prompt-visibility { hidden: boolean }` → 200 `Character`. **Ревизия не растёт**: это не правка профиля, истории у флага нет, и рост ревизии давал бы 409 открытой карточке.
- Единственная точка фильтра — `packages/agents/src/character.ts`, `gatherCharacterContext`: скан участников идёт по `WHERE book_id = ? AND hidden_from_prompts = 0`. `alwaysIncludeIds` (POV из плана) фильтр обходит: POV назван автором явно.
- Не фильтруется: `loadCanonCast` (планировщику нужен весь состав — иначе он выдумает замену), `cast_check` (сравнивает утверждённых героев), резолвер фактов (факт о скрытом герое всё равно привязывается к нему — иначе он пришился бы чужому).
- Экран: кнопка-глаз в карточке героя (`Eye`/`EyeOff` из lucide), подпись «В запросах» / «Скрыт из запросов».

## 4. «Описать» — одна сенсорная деталь по каналу

**Что у Литраба.** Выделить фразу, выбрать канал (зрение, слух, обоняние, вкус, осязание, метафора) — модель вплетает ровно один слой, не переписывая остальное. Текст ПОСЛЕ фрагмента намеренно не видит: её дело насытить написанное, а не продолжить.

**Что у нас.** `inline`: continue/rewrite/shorten/intensify/lengthen. «Развернуть» специально уведён от нагромождения ощущений (де-AI слой: сенсорная плотность — машинный признак). Точечного инструмента «одна деталь одного канала» нет.

**Решение.**
- `packages/shared/src/inline.ts`: команда `"describe"` (подпись «Описать»), требует выделения; `senseChannelSchema = z.enum(["sight","sound","smell","taste","touch","metaphor"])`, `SENSE_CHANNEL_LABELS`; `runInlineCommandInputSchema.sense: senseChannelSchema.optional()`.
- Маршрут: `describe` без `sense` — 400 `bad_request`. Для `describe` `afterText` заменяется пустой строкой до вызова агента.
- `packages/agents/src/inline.ts`: инструкция строится функцией `describeInstruction(sense)`: оставить фразу как есть, вплести ОДНУ деталь канала, конкретную и привязанную к месту и герою, не из штампов; не добавлять событий и реплик, не объяснять ощущение; длина — фрагмент плюс не больше одного предложения; вернуть фрагмент целиком. Для `metaphor` — одно бытовое, предметное сравнение, без книжной приподнятости. Блок «Текст ПОСЛЕ» в промпте для `describe` не печатается.
- Экран: кнопка «Описать» раскрывает шесть кнопок каналов; выбор канала запускает команду.

Правило де-AI сохраняется: один канал, одна деталь — инструмент против «сцены-схемы», не для «перегруза».

## 5. Что потеряла правка

**Что у Литраба.** Три проверки после правки: список «особенно важно сохранить», объём (просили убрать повторы, а стало на 15% короче — модель убрала лишнее), реплики отдельно. Плюс предупреждение «глава сократилась» с откатом.

**Что у нас.** `protectedFragments` + `survivingFragments` на сервере, `protectedLost` уходит в событии `done` — **и не показывается ни одной панелью**. Дельты объёма нет. Пропавших имён нет.

**Решение.** Сервер не меняется (кроме `wordCount`, который уже есть).
- `streamRepair` в клиенте отдаёт `protectedLost?: string[]` в `onDone`; `CritiquePanel` хранит и передаёт в `ProposalPanel`.
- `ProposalPanel` — новые необязательные пропсы: `baseWordCount: number | null`, `protectedLost?: string[]`, `characterNames?: string[]`.
- `packages/shared/src/prose-diff.ts`: `findLostMentions(changes, candidateText, names): string[]` — имена (по `mentionsEntityName`), встречавшиеся в убранных/заменённых абзацах базы и не встречающиеся в кандидате.
- Панель печатает: «Объём: 1895 → 1610 слов (−15%)»; для `kind === "repair"` при сокращении больше 10% — «Правка убрала больше десятой части текста — проверьте, что пропало»; «Защищённое не дожило: …»; «Из правленных абзацев исчезли имена: …». Пустые строки не печатаются.
- `ChapterPage` передаёт `baseWordCount={chapter.currentVersion?.wordCount ?? null}` и имена героев (список уже грузится для подсветки канона) в обе панели.

## 6. Паспорт стиля устаревает

**Что у Литраба.** Стиль меняется по ходу книги; портрет, собранный на третьей главе, к двадцатой тянет автора назад. Хороший стиль-гайд отстаёт от рукописи максимум на несколько глав; пересобирать — по фрагментам последних глав.

**Что у нас.** `style_profiles.last_extracted_at` есть, признака устаревания нет, пути «добрать последние главы в корпус» нет.

**Решение.**
- `GET /books/:id/style-freshness` → `{ profileId, profileName, kind, lastExtractedAt, versionsSince, chaptersSince, stale }`; `profileId: null`, если у книги нет профиля. `versionsSince` — версии глав книги, созданные после `last_extracted_at`; `chaptersSince` — сколько разных глав; `stale = kind === "extracted" && lastExtractedAt !== null && chaptersSince >= 3`. Блендам устаревание не считается (у них нет своего корпуса).
- `POST /books/:id/style/refresh-from-chapters` → берёт до трёх последних по `order_index` глав с принятой версией, склеивает `content_text`, прогоняет через `parseReference("<книга>-главы.txt", text)` и кладёт корпусом в профиль книги через хелпер `insertReferenceCorpus` (`apps/server/src/utils/style-corpus.ts`, вынесен из маршрута загрузки корпуса и используется обоими). Ответ `{ corpusId, chapters: [{ id, title }] }`. Старые корпуса **не удаляются**: статистика меряется по всему корпусу, и автор вправе убрать старое руками.
- Извлечение вызывает клиент существующим `POST /style-profiles/:id/extract` вторым шагом — маршрут не дублируется.
- Экран: строка «Стиль «X» собран до N принятых глав» с кнопкой «Пересобрать по последним главам» (`StyleFreshnessNote` в правой колонке главы). Показывается только при `stale`.

## 7. Чат по книге

**Что у Литраба.** Главный инструмент: чат справа видит Досье и открытую главу; советчик (развилка, мотивация), соавтор (план главы, сцена по инструкции), редактор (повторы, ритм). В текст не пишет.

**Что у нас.** Ни одного места «обсудить» — только кнопки конвейера. Сборка контекста при этом уже одна, `assembleGenerationContext`; чат — тонкий потребитель.

**Решение.**
- Таблицы (миграция 0032): `chat_threads (id, book_id FK, chapter_id FK NOT NULL, title, created_at, updated_at)`, `chat_messages (id, thread_id FK CASCADE, role CHECK IN ('user','assistant'), content, created_at)`. Тред привязан к главе — чат живёт на странице главы и видит её текст.
- Маршруты (`apps/server/src/routes/chat.ts`): `GET/POST /chapters/:id/chat/threads`, `DELETE /chat/threads/:id`, `GET /chat/threads/:id/messages`, `POST /chat/threads/:id/messages { content }` — SSE: `chunk`, `done { message }`, `error`, `ping` раз в 20 с.
- Контекст: `assembleGenerationContext` с `scanTexts: [текст главы, вопрос]`, `retrievalQuery: вопрос`, `notesQuery: вопрос`, `povName: null`, `styleFewShot: 0`, `factsBoundary: "at_chapter"`, `includeAuthorPlan: true`, `label: "chat"`. Переполнение обязательного слоя — 400 тем же текстом, что у Писателя. Текст главы — черновик, если есть, иначе принятая версия; не больше 40 000 символов, обрез помечается строкой.
- История — последние 20 сообщений треда, в переменной части промпта. Треды друг о друге не знают (решение Литраба, принимаем: дешевле и вчерашние ошибки не едут дальше).
- Агент `book_chat` (`packages/agents/src/chat.ts`): текстовый, через `streamText`, бэкенд `subscription`, модель — `plotModel` книги (разговор, не проза). Правила: отвечать по материалам книги и говорить «в материалах этого нет», а не выдумывать; цитировать текст главы при разборе; предлагать прозу только по просьбе и в стиле книги; коротко; ничего не менять в главе самому.
- Название треда — первые 60 символов первого сообщения.
- Экран: `ChatPanel` в правой колонке главы: выбор треда, «Новый разговор», удаление, лента, поле ввода, Ctrl+Enter.

Не делаем: `#`-упоминания других глав и карточек (потолок: ответ «в материалах нет» на вопрос про главу 3, когда открыта 12-я; лечится потом кнопкой «приложить главу»).

## 8. Глава по беатам

**Что у Литраба (и у процитированных авторов).** Работа битами по 500–800 слов с подтверждением: на длинной генерации сползают голоса, ритм и детали; короткие куски автор проверяет целиком.

**Что у нас.** Глава пишется одним вызовом на 3–5 тысяч слов. Абзацы кандидата принимаются частично, но модель всё равно пишет всё разом.

**Решение.** Режим «По беатам» у кнопки «Написать главу».
- `writeChapterInputSchema`: `mode: z.enum(["whole","beats"]).default("whole")`, `fromBeat: z.number().int().nonnegative().optional()` (только для `beats`; префикс — текст принятой версии).
- `prose_proposals.beats_done INTEGER NULL`, `beats_total INTEGER NULL` (миграция 0032); `ProseProposal.beatsDone/beatsTotal`.
- Писатель: `WriteChapterInput.beat?: { index, textSoFar }`; в переменной части промпта для беата: уже написанное дословно (продолжать с этого места, не повторять), «сейчас пиши ТОЛЬКО беат N из M», остальные беаты — ориентир, объём ≈ `estimatedWords / beats.length`, для не-последнего — «не завершай главу», для последнего — финал главы. Контракт и замысел сцены остаются. Стабильная часть промпта та же — кэш-префикс переживает все вызовы главы.
- Маршрут `POST /chapters/:id/write` при `mode: "beats"`: один кандидат; цикл по беатам от `fromBeat`; перед каждым — событие `beat { index, total }`; текст беата дописывается в `content_text` кандидата сразу (`appendProposalProgress`) — падение процесса не теряет написанное; после каждого беата проверяются `shouldStop` (отмена: как сейчас, кандидат `cancelled`) и `shouldHold`.
- Остановка с сохранением — `POST /prose-proposals/:id/hold`: реестр отмены получает `requestHold/shouldHold`; поток дописывает текущий беат и завершает кандидата `incomplete` с `stopReason: "held"`, `beatsDone = k`; событие `done { proposal, held: true }`. Отличие от `cancel`: текст остаётся и принимается.
- Дописать: `POST /chapters/:id/write { mode: "beats", fromBeat: k }` — префикс берётся из **принятой версии** главы (автор принял частичный кандидат), итоговый кандидат — префикс плюс новые беаты, принятие заменяет версию как обычно. Экран находит, с какого беата продолжать, по последнему принятому кандидату главы (`acceptedVersionId === currentVersionId && beatsDone < beatsTotal`) — переживает перезагрузку без новых колонок у версии.
- Экран: переключатель «Целиком / По беатам» (localStorage `bf-write-mode`), строка «Беат 3 из 7», кнопка «Остановить после беата», в панели кандидата «Написано беатов: 3 из 7», после принятия — «Дописать с беата 4».

## Чего не берём (и почему)

- Long-context вместо памяти — у нас границы сцены, события знаний, контракт, манифест источников; длинный контекст их не заменит и на 30 главах дороже.
- Критик арки персонажа — уровень 2 отложен вне MVP (locked decision).
- Потолки знаков у карточек, 5-часовые лимиты — про их тарифы.
- Хранить исходный образец стиля вместо портрета — у нас образцы уже в кэш-префиксе и отбираются стабильно; их довод про утечку содержания снят тем, что образцы берутся из авторского корпуса, а не из чужого.
