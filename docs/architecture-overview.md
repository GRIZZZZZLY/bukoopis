# book-forge — архитектурный обзор (бриф для внешнего обсуждения)

> Самодостаточный документ. Читателю не нужен доступ к репозиторию.
> Актуально на 2026-07-12, ветка `feat/redesign-phase-0`.

## 1. Что это

`book-forge` — локальный (local-first), однопользовательский инструмент для написания
романов с помощью LLM. Русскоязычный MVP. Пользователь проходит структурированный
7-стадийный воркфлоу (от концепта до глав), а набор LLM-агентов помогает генерировать
и критиковать текст. Ключевая ценность — **сквозная память**: модель «помнит» лор, канон
и сюжет между главами, а не только последние абзацы.

**Жёсткие ограничения (осознанные, не временные):**
- Только русский язык, один пользователь, без аутентификации/мультиарендности.
- Единственный секрет — `ANTHROPIC_API_KEY`. Подписка Pro/Max НЕ оплачивает вызовы кастомного бэкенда.
- Вне scope: Obsidian/MCP file-watcher, ветвление-UI, второй язык, Docker/CI, арки уровня 2.

## 2. Технологический стек

- **Монорепо:** pnpm workspaces, Node 22 LTS, ESM only, TypeScript strict (`noUncheckedIndexedAccess`).
- **Сервер:** Hono (HTTP), `better-sqlite3` (синхронный драйвер, WAL), опционально `sqlite-vec` (векторный поиск).
- **БД:** один файл SQLite. Drizzle ORM — только для описания схемы (`schema.ts`) и типов; в рантайме — прямой `sqlite.prepare().run/get/all`. JSON хранится как TEXT.
- **Веб:** React 18 + Vite 6 + Tailwind v4 (CSS-first, без `tailwind.config.js`) + TipTap (редактор) + react-router-dom@7. shadcn/ui как исходники в репо.
- **Эмбеддинги:** локальная ONNX-модель `Xenova/paraphrase-multilingual-MiniLM-L12-v2` (384-dim) через `@huggingface/transformers`, кэш в `~/.cache/book-forge-transformers`. Фоллбэк — детерминированная заглушка (`EMBEDDING_PROVIDER=stub`).
- **LLM — гибридный роутинг по агентам (НЕ «только API» и НЕ «только подписка»):** большинство текстовых/aspect/memory-агентов по умолчанию идут через **subscription** (Claude Pro/Max по `claude login`; `ANTHROPIC_API_KEY` вырезается из env перед вызовом SDK; учитывается как zero-cost). Структурные агенты Plot/критики/canon_guard/style_extractor/lore/character по умолчанию — через **прямой Anthropic API** (нужен `ANTHROPIC_API_KEY`, биллинг по токенам). Роутинг переопределяется env `LLM_AGENT_BACKEND_MAP`. Модели: Writer = Opus (`claude-opus-4-7`), Plot/критики = Sonnet (`claude-sonnet-4-6`). Opus 4.7 не принимает `temperature` (передаётся условно).

## 3. Структура монорепо

```
apps/
  server/   — Hono API + БД + миграции + скрипты
  web/      — React SPA
packages/
  shared/       — Zod-схемы, типы, инварианты (общие для server+web)
  llm/          — диспетчер LLM, контракты агентов, 2 бэкенда, retry
  agents/       — реализации агентов + bootstrap (регистрация контрактов)
  retrieval/    — чанкинг, эмбеддинги, гибридный поиск, индексация
  style-engine/ — извлечение стилевого профиля из референс-корпуса
```

**Граф зависимостей (без циклов):**
`shared → llm → {agents, style-engine} → server`; `web → shared`.
Импорты только через `workspace:*` и поле `exports` пакета — запрещено лезть в `src/` чужого пакета.

## 4. Серверная архитектура

- Точка входа `apps/server/src/index.ts`: ДО создания приложения регистрирует контракты всех
  структурированных агентов (`registerAllAgentContracts()` + `registerStyleExtractorContract()`)
  и проверяет полноту (`assertAllStructuredAgentsHaveContracts()`), затем поднимает Hono-приложение и ONNX-провайдер эмбеддингов.
- Одно соединение с БД (`better-sqlite3`, WAL, `foreign_keys=ON`, `busy_timeout=5000`).
- Роуты под `/api`: `health, books, chapters, plot, retrieval, import-export, entities, critique, inline, style, usage, canon-extraction, studio`.
- Валидация входа на каждой границе — Zod `safeParse` (без глобального error-middleware; роуты обёрнуты в try/catch).

## 5. LLM-слой (диспетчер + контракты)

- Каждый агент со структурированным выводом регистрирует `AgentStructuredContract`
  (входная схема, выходная схема, системный промпт, MCP-спецификация инструмента).
- `dispatchStructured({ agentName, payload, model })` маршрутизирует вызов и валидирует ответ по выходной схеме.
- **Два бэкенда, выбор per-agent** (`router.ts` → `DEFAULT_AGENT_BACKEND`):
  - **subscription** (Claude Pro/Max по `claude login`; `ANTHROPIC_API_KEY` удаляется из env перед вызовом `@anthropic-ai/claude-agent-sdk`; usage помечается `subscription:` → zero-cost): `writer, editor, inline, summarizer, concept_refiner, aspect_playbook/variants/refine/entity_variants, canon_fact_extractor, episodic_note_extractor, reranker`. Структурный вывод здесь — режим `mcp_submit_tool` (модель кладёт результат в MCP-инструмент, есть self-repair в том же ходе).
  - **api** (прямой Anthropic API, требует `ANTHROPIC_API_KEY`, биллинг по токенам): `plot_outline, plot_chapter_plan, canon_guard, critic_canon, critic_style, critic_editor, critic_reader, style_extractor, lore, character`. Выбраны для надёжного структурного `tool_use`.
  - Переопределяется env `LLM_AGENT_BACKEND_MAP` (бэкенд per-agent) и `LLM_SUBSCRIPTION_STRUCTURED_MODE_MAP` (режим структуры на subscription). Есть и гибрид `generateThenStructure`: генерация прозы на subscription → дешёвое извлечение JSON на api (~$0.001/вызов).
- **Retry** (p-retry, экспоненциальный backoff, 429/5xx/сеть) подключён к API-пути; на subscription-бэкенде ретраев пока НЕТ (известный пробел).
- Добавление агента = запись в `AGENT_NAMES`/`STRUCTURED_AGENT_NAMES` + контракт + регистрация в `bootstrap.ts`; drift-guard-тест следит за паритетом.

**22 агента (`AGENT_NAMES`):**
`plot_outline, plot_chapter_plan, lore, character, writer, editor, inline, summarizer, canon_guard,
critic_canon, critic_style, critic_editor, critic_reader, style_extractor, concept_refiner,
aspect_playbook, aspect_variants, aspect_refine, aspect_entity_variants,
canon_fact_extractor, episodic_note_extractor, reranker`.
Свободнотекстовые (`writer, editor, summarizer, inline, lore, character`) не требуют контракта; остальные — структурированные.

## 6. Studio-воркфлоу

Маршрут `/books/:id/studio`. Заменил старую цепочку title→outline→chapter на 7 стадий:
**concept → world → lore → characters → items → plot → chapters.**

- `world`/`lore` — markdown-пейлоады; `characters`/`items` — `entity_set`, материализуются в канон-таблицы (`characters`, `items`).
- Состояние в `books.studio_state` (JSON). **Оптимистичная блокировка**: счётчик `revision`; PATCH требует `expectedRevision`, при расхождении — 409.
- Жёсткие инварианты (`packages/shared/src/studio-invariants.ts`) проверяются перед каждым persist; мягкие предупреждения — `studio-warnings.ts`.
- Двухслойный aspect-движок: `StageAdapter<TPayload>` (renderVariant/renderFinal/payloadSchema) + оркестраторы `AspectRunner` / `EntityStageRunner`.
- Все изменения аудируются в `studio_events` (тип события, revision до/после).
- Plot/Writer/Critique подтягивают `loadStudioContext` → концепт + принятые (accepted) world/lore аспекты.

## 7. Пайплайн памяти / контекста (ключевое)

Контекст для генерации главы собирается из нескольких слоёв (все идут в промпт Writer/Plot):

1. **Studio-контекст** — `books.concept` + принятые world/lore аспекты из `books.studio_state`. Постоянный.
2. **Rolling window** — последние 3 главы своими поглавными сводками (`chapter_versions.summary`, при её отсутствии — начало текста) + свёртка (`book_meta_summaries`) для всего, что старше. Свёрток у книги несколько — по одной на пройденный рубеж (`covers_to_order`, миграция 0025), и сцена берёт ту, что кончается ДО её границы: одна свёртка на книгу для ранней главы пересказывала будущее. Отпечаток источников свёртки (версии и названия глав) сверяется и при чтении. Дословно едет только **хвост предыдущей главы** (`loadPreviousChapterTail`).
3. **Retrieval** — гибридный поиск по прошлым главам: FTS5 (`chunk_fts`) + вектор (`chunk_vec`, sqlite-vec), слияние через Reciprocal Rank Fusion. `beforeChapterOrder = currentOrder-1` предотвращает утечку самой себя. Из результатов исключается только глава, поданная дословно (`verbatimChapterOrders`), а не всё окно: окно даёт пересказы, и деталь, не попавшая в пересказ, иначе недостижима (AC-12).
4. **Темпоральный канон** — `book_facts` со сроком действия (`valid_from`/`valid_to_chapter` + `superseded_by`). Питает Writer и Canon-Guard.
5. **Эпизодические заметки** — `book_notes` (нити/предвестия/арки/темы/загадки), эмбеддятся в `book_notes_vec`. Питают Plot и критика-читателя.
6. **Reranker** — LLM-судья над пулом retrieval/notes. **Выключен по умолчанию** (`RETRIEVAL_RERANK=1` включает).
7. **Одна сборка на все роли** (этап 4, 2026-09-19) — `apps/server/src/utils/generation-context.ts`, `assembleGenerationContext`. Writer, критики и Reviser получают одну историю (слои 2–5 + события знаний героев на границе сцены), один бюджет (`MAX_PROSE_CONTEXT_TOKENS`, обязательный слой — участники с фактами; переполнение → 400 до первого токена) и различаются только представлением: что сканировать и чем искать. На каждую сборку пишется **манифест источников** (`context_manifests`, миграция 0026): версии глав, ревизии героев и отношений, события, стиль, отпечаток набора. Манифест Writer'а привязывается к версии при принятии кандидата; критика сверяет с ним свой и отдаёт в отчёте `baseChanged` (true / false / null — «сравнивать нечем»). Текст промпта не хранится: всё, на что указывает манифест, версионировано.

**Экстракторы (fire-and-forget, запускаются при finalize главы):**
после сохранения финальной версии срабатывает цепочка `summarizer` → meta-summary rollup →
`canon_fact_extractor` → `episodic_note_extractor`. Все падают молча (не ломают сохранение),
логируют warn. **Пробел:** нет ретраев/очереди/dead-letter → при сбое факт/заметка тихо отсутствуют.

**Finalize-gate (важная деталь UX):** автосейв (debounce 10с) сохраняет только черновик-версию,
БЕЗ индексации и экстракторов. Тяжёлая работа (chunk+embed+извлечения) идёт только при явном
«Сохранить»/Ctrl+S (`finalize:true`). Это убирает «ре-эмбеддинг + 3 LLM-вызова на каждую паузу набора»,
но требует привычки финалить главу, иначе она не попадёт в память.

**Деградация при недоступности модели эмбеддингов:** ничего не падает — индексация вставляет чанки
для FTS (пропуская векторы), поиск сводится к FTS-only, при загрузочной ошибке — разовый warn.

```
                          │        (контекст одной главы N)        │
                          └──────────────────▲───────────────────┘
                                             │  склейка слоёв
   ┌───────────┬───────────────┬─────────────┴────┬──────────────┬─────────────┐
   │           │               │                  │              │             │
┌──┴────┐ ┌────┴─────┐  ┌───────┴──────┐   ┌───────┴──────┐ ┌─────┴─────┐ ┌─────┴────┐
│Studio │ │ Rolling  │  │  Retrieval   │   │ Канон-факты  │ │Эпизодич.  │ │ Reranker │
│контекст│ │ window   │  │  (гибрид)    │   │ book_facts   │ │ заметки   │ │  (off)   │
└──┬────┘ └────┬─────┘  └───────┬──────┘   └───────┬──────┘ └─────┬─────┘ └─────┬────┘

   │       rollup              │                  │              │          пул выше)
```

**Цепочка извлечения при finalize (Ctrl+S), всё fire-and-forget:**

```
finalize=true → INSERT chapter_versions
      │
      ├─ chunk + embed ─────────────────→ chunks · chunk_vec · chunk_fts
      │
      └─ фоновая цепочка (не блокирует ответ, warn в лог при сбое):
           summarizer ─────────────────→ chapter_versions.summary
                │
                ├─ meta-summary rollup ──→ book_meta_summaries
                ├─ canon_fact_extractor ─→ book_facts   (+ supersede старых)
                └─ episodic_note_extractor → book_notes (+ book_notes_vec)

   Автосейв (debounce 10с) → INSERT chapter_versions (finalize=false)
                             └─ БЕЗ индексации и без экстракторов (только черновик)
```

## 8. Схема БД (SQLite)

**Ядро:** `books` (title, language, premise, outline_json, style_profile_id, status,
writer_model/plot_model/critic_model ∈ {sonnet,opus}, writer_provider ∈ {anthropic,ollama},
concept TEXT, studio_state TEXT) · `chapters` (book_id, order_index, title, intent, plan_json,
current_version_id, status ∈ {draft,in_review,final}) · `chapter_versions` (chapter_id,
parent_version_id, content_json, content_text, word_count, source ∈ {manual,agent}, summary).

**Канон/знания:** `characters`, `locations`, `items` (profile_json) · `relationships`
(from/to character, type, tension, notes) · `hooks` (description, status ∈ {open,mentioned,resolved,deferred},
expected_resolution_chapter_order) · `character_knowledge` (fact, learned_in_chapter_id) ·
`entity_chapter_mentions` (entity_type, entity_id, chapter_id, mention_count, quote).

**Извлечение/критика:** `chapter_canon_extractions` (payload_json, status, cost/tokens) ·
`critique_reports` (chapter_version_id, status ∈ {pending,done,error}, report_json).

**Retrieval:** `chunks` (book_id, source_type ∈ {chapter_version,reference}, source_id, chapter_id,
chapter_order, text, offsets, token_count, is_reference).

**Память (миграции 0011–0013):** `book_meta_summaries` (свёртка старых глав) ·
`book_facts` (темпоральные факты) · `book_notes` (эпизодические заметки).

**Стиль:** `style_profiles` (fingerprint_json, fatigue_words_json) · `reference_corpora` ·
`reference_scenes`.

**Прочее:** `llm_usage` (учёт токенов/стоимости по route/model/book) · `studio_events` (аудит) · `_health`.

**Виртуальные таблицы:** `chunk_fts` (FTS5, unicode61, remove_diacritics) ·
`chunk_vec` (vec0, float[384]) · `book_notes_vec` (vec0, float[384]).

**Миграции — ручной plain-SQL** (официальный процесс). Рантайм-мигратор читает
`meta/_journal.json` + `.sql`-файлы (снапшоты Drizzle сломаны с 0008, `drizzle:generate` НЕ использовать).
`pnpm migrate` перед применением делает бэкап (`VACUUM INTO`, хранит 10 последних).

## 9. Поток данных: генерация одной главы (end-to-end)

1. Пользователь на стадии `chapters` задаёт intent → `plot_chapter_plan` строит план (видит studio-контекст + retrieval + открытые нити).
2. `writer` стримит текст главы; в промпт собраны 4 слоя памяти (§7).
3. Критики (`critic_canon/style/editor/reader`) и `canon_guard` дают отчёт (`critique_reports`).
4. Автосейв (10с) пишет черновик-версию (`chapter_versions`, `finalize:false`).
5. Явное «Сохранить»/Ctrl+S (`finalize:true`): чанкинг+эмбеддинг → `chunks`/`chunk_vec`,
   затем fire-and-forget цепочка экстракторов → `summary`, `book_meta_summaries`, `book_facts`, `book_notes`.
6. Следующая глава уже «видит» этот материал через retrieval/rolling/канон.

## 10. Известные ограничения и открытые вопросы (темы для обсуждения)

- **Надёжность памяти:** экстракторы без ретраев → возможны тихие дыры в каноне на длинной книге. Нет индикатора «глава в памяти / нет».
- **Retry только на API-пути**, subscription-бэкенд падает на 429 сразу.
- **Материализация сущностей** (characters/items) — цикл INSERT без единой транзакции; canon-insert и PATCH studio-state неатомарны (риск осиротевших сущностей).
- **Токен-бюджет один и общий** (`MAX_PROSE_CONTEXT_TOKENS` = 80 000) для всех ролей, но не зависит от возможностей конкретной модели — бюджет по бэкенду остаётся открытым (раздел 8.4 ТЗ). Дублирование retrieval и окна снято: исключается только глава, поданная дословно.
- **Синхронный KNN** (sqlite-vec brute-force, без ANN) блокирует event loop; фильтр `book_id` применяется после KNN (недобор кандидатов).
- **Reranker выключен** — качество retrieval на голом RRF.
- **Фронтенд:** нет code-splitting; `ChapterPage` (~1080 строк) полностью ре-рендерит на каждый токен стрима/нажатие.
- **Инлайновый SQL** размазан по «толстым» роутам (только studio имеет репозиторий).

## 12. Приложение: реальные системные промпты

Извлечено дословно (verbatim) из исходников. Шаблонные интерполяции `${...}` сохранены как есть — они показывают, какие данные подставляются в момент вызова. Русский текст воспроизведён побуквенно.

### writer — packages/agents/src/writer.ts

Пишет прозу главы по beat-sheet; собирает системный промпт из константы + слоёв контекста книги (кэшируется), а volatile-часть несёт метаданные конкретной главы.

Системная константа `SYSTEM_WRITER`:

```text
Ты — Writer Agent. Пишешь художественную прозу на русском языке.

Получаешь: контекст книги + beat-sheet главы + (опционально) краткое содержание предыдущих глав.

Твоя задача: написать связный текст главы, точно следуя последовательности beats. Каждый beat = логический блок прозы, обычно 1-4 абзаца.

Требования:
— Не пересказывай beats — превращай их в живую сцену с диалогами, действием, описаниями.
— Соблюдай POV из beat-sheet.
— Стиль: ясный, без избыточных метафор, без LLM-клише ("казалось", "по сути", "не X, а Y", избытка списков из трёх).
— Целевой объём — близко к estimatedWords ± 30%.
— Не выводи никаких служебных пометок, заголовков, списков beats. Только сама проза, разделённая на абзацы.
— В начале не повторяй название главы.

Пиши прозу сразу. Без вступлений типа "Вот глава:".
```

```text
- "closed" — открытый ранее крючок закрыт в главе
```

```text
- Выделяй ОТЛИЧИЯ от среднего LLM-выхода, а не общие литературные правила.
- Давай конкретные операционные подсказки ("предложения средней длины с инверсией в начале каждого 3-4-го") вместо абстракций ("живой стиль").
- voiceSummary — 2-3 предложения, как ты бы описал голос автора другу-писателю.
- thingsToImitate — 5-10 КОНКРЕТНЫХ паттернов (синтаксис, ритм, переходы), которые надо воспроизвести.
- thingsToAvoid — 5-10 паттернов, которыми Writer обычно грешит и которых у этого автора НЕТ.
- metaphorFamilies — категории метафор (например "природные стихии", "телесные ощущения"), а не сами метафоры.
- signatureSyntax — частотные синтаксические конструкции автора (например "обрывы прямой речи многоточием", "длинные перечисления через тире").
- signatureTropes — повторяющиеся литературные приёмы (например "сцена начинается с описания погоды").

Возвращай structured output по схеме.
```

User-промпт (`buildStyleExtractorPrompt`, строки соединены `\n`; `sceneBlock` — сцены вида `### Scene ${i + 1}\n${s}`, соединённые `\n\n---\n\n`):

```text
Автор: ${input.authorName}
Язык: ${input.language}
Количество сцен в выборке: ${input.scenes.length}

Проанализируй корпус и верни style fingerprint в structured формате.

Корпус:
${sceneBlock}
```
