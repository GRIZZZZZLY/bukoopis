# Структурные маркеры ИИ-прозы: baseline

`measureStructuralTells` ([packages/style-engine/src/tells.ts](../packages/style-engine/src/tells.ts)) считает конструкции, которые Writer воспроизводит вопреки запретам в промпте. Замер 2026-09-04 по протоколу sepia (StoryScope) показал: лексические запреты из `prose-rules.ts` держатся («казалось» 2–3 на главу, остальные маркеры 0), структурные игнорируются. Конструкцию нельзя запретить, но можно измерить: критик получает цитаты вместо впечатления, правка промпта получает число, которое должно сдвинуться.

Все счётчики эвристические, по поверхностным формам русского текста. Их смысл в сравнении версий одного текста, не в абсолютном вердикте.

## Baseline: «Тёмный лес», глава 1, три версии Writer (opus, 2026-05-08/09)

Тексты сгенерированы до появления части текущих правил `prose-rules.ts`. Числа фиксируют точку отсчёта до любых правок Plot/Writer.

Сцены: в текстах нет разделителей, поэтому каденция считается по пяти равным кускам абзацев. Ручные подсчёты sepia-review дали те же порядки для сравнений и зачинов, выше для «не X, а Y» (ручной счёт включал стаккато «Не X. Y.») и для правила трёх (ручной счёт включал триады из фраз длиннее двух слов). Счётчик эмоций через тело ловит лексическую подмножество: существительное тела рядом с аффект-глаголом, без метафор вроде «жёрнов».

## Что считается

| id | форма | известный шум |
|---|---|---|
| `negativeParallelism` | «не X, а Y», «не X — а Y», «не X, не Y, а Z» (один раз), «не только… но и», «Это был не X. Это был Y.» | нет; временные «, а когда/потом/если» исключены |
| `triad` | три однородных члена по 1–2 слова «X, Y и Z»; три подряд коротких предложения с одним зачином | обычные перечисления людей тоже считаются |
| `simile` | будто, словно, точно, подобно, напоминал, похож на, как будто, как бы | «точно» в значении «именно»; «как» не считается вовсе |
| `filterVerb` | понял, знал, чувствовал, почувствовал, осознал, заметил, увидел, услышал, подумал, ощутил | увидел/услышал в чистом действии |
| `participialClause` | клауза, начинающаяся с деепричастия: -ясь, -вшись, -вши, -учи/-ючи, -ивая/-ывая, -яя кроме -няя, -ав/-ев/-ив/-яв/-ув со строчной | деепричастия на -ая после других основ (перетирая, глотая) не ловятся |
| `embodiedEmotion` | существительное тела в 4 словах от аффект-глагола в любом порядке; «мурашки» | буквальные действия («сжал кулак» как жест) |
| `etoBylOpener` | предложение начинается с «Это был(а/о/и)» | нет |

Ритм: `shortSentenceShare` (≤3 слов), `punchParagraphShare` (абзацы ≤6 слов без реплик диалога), `sceneCadence.spread` = (max − min) / mean средних длин предложений по сценам.

## Где используется

- Маршрут критики ([apps/server/src/routes/critique.ts](../apps/server/src/routes/critique.ts)) считает блок по тексту версии и передаёт его в `CriticInput.structuralTellsContext`. Читает его только Style-критик: цитаты берёт оттуда, ранжирует по частоте, ориентиры из таблицы выше зашиты в его системный промпт.
- Общая калибровка критиков `CRITIC_CALIBRATION_RULE` ([packages/agents/src/critics/base.ts](../packages/agents/src/critics/base.ts)): сигнал только с цитатой, кластер вместо единичного попадания, тире и предписанный стилем плотный синтаксис не дефект, перегиб отмечается отдельно.
- Архитектурный лист outline и `closing` beat-sheet ([packages/shared/src/plot.ts](../packages/shared/src/plot.ts)) закрывают уровень выше стиля: Plot принимает структурные решения явно, Writer получает их по-русски и держит правила финала, регистра и «слабины».
- Reviser ([packages/agents/src/reviser.ts](../packages/agents/src/reviser.ts)) несёт те же правила в зеркальном виде и получает `architectureContext`: repair — последний проход по прозе, и именно там хвост рефлексии или выглаженный ритм возвращаются обратно. Решение о финале доходит до него внутри блока beat-sheet.

## Что проверено и отвергнуто

Две попытки поднять полноту счётчиков не прошли проверку на реальных главах (2026-09-04):

- **Параллельные триады через запятую** (три однородных члена равной длины в словах, как прокси параллельности): 0 / 1 / 0 попаданий на трёх версиях, и единственное — ложное. Ручной подсчёт 25 / 8 / 18 считал риторические триады через предложения и клаузы, которые regex надёжно не видит. Разрыв между ручным и машинным счётом здесь закрыть нечем.
- **Стаккато-отрицание** («Не коснулся. Только провёл.»): 2 / 4 / 1 попадание, точность ~70% (ложные — императивы «Не ходи. Закрой уши.» и обрывы, за которыми идёт несвязанное повествование). Прибавка к `negativeParallelism` около 0.5 на 1000 слов не оправдывает пересчёта полос severity, откалиброванных по текущему определению.

Вывод: счётчики остаются precision-first. Если полосы будут пересчитываться по другой причине, стаккато-форму стоит добавить тем же проходом.

## Как пересчитать

Из любого места с доступом к workspace:

```ts
import { measureStructuralTells, renderStructuralTells } from "@book-forge/style-engine";
const report = measureStructuralTells(chapterText);
console.log(renderStructuralTells(report));
```

Тексты глав лежат в `chapter_versions.content_text`. Baseline-версии: id 1, 2, 3 книги «Тёмный лес» в локальной БД.
